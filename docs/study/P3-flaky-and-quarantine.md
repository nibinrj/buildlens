## Infra attribution before detection

Classify the bounded (1 MiB) log tail before rule/release calculations. Exclude every result
in an infra build. Otherwise one agent incident becomes many apparent flaky tests.
This also excludes a real bug in that build: a conservative false negative.

| Rule | Signal | False positives/guards |
| --- | --- | --- |
| Agent lost | Remoting exception or Jenkins offline/removal/cancellation | Mere mentions or assertion messages insufficient |
| OOM | Process exit 137 or OOMKilled=true | Bare 137 and OOMKilled=false excluded; another SIGKILL may still match |
| Disk full | OS/I/O diagnostic No space left on device | Quoted assertions and examples excluded |
| Docker unavailable | Docker/Testcontainers daemon connection diagnostic | Quoted assertions excluded |
| Dependency timeout | Maven artifact transfer/resolution with network timeout on the same diagnostic line | Test timeout, missing artifact and 404 insufficient |

Tail truncation can hide incidents. Arbitrary stdout can mimic diagnostics. Multi-line dependency
diagnostics with separated cause text may be missed. These are explainable attribution heuristics,
not proof of root cause. Actual Spot events arrive in J.5.

## Detection and evidence

| Rule | Default | False positives |
| --- | --- | --- |
| R1 | At least 2 FLAKY builds in last 30 non-infra test runs | Stateful bugs may pass reruns |
| R2 | PASSED and FAILED/ERROR on same tested tree in last 30 non-infra runs | Tree excludes external configuration/services |
| R3 | At least 3 pass/fail flips in last 30 eligible default-branch runs | Several real break/fix cycles may trigger |

[decision] Order by started_at then build id. Filter infra before windows.
R3 filters non-default, FLAKY and SKIPPED before its window; FAILED/ERROR are one category.
A genuine break then fix gives 2 flips and must not trigger. R2 uses tested_tree_sha (D-078)
and ignores missing trees. SQL returns the union of bounded recent and eligible main histories,
so a flood of PR runs cannot hide R3 evidence. Preserve build IDs, trees, outcomes and hashes.
Strict optional config.yaml rejects unknown keys, multiple documents, oversized files and
impossible thresholds. Compose mounts this file; a restart applies policy changes.

## Quarantine safety and lifecycle

D-077: cap = min(max_tests, max(1, floor(percent / 100 * recently seen distinct tests))).
Defaults are 5%, 10 tests and the last 30 repo builds. No observed test means no candidate.
All active rows, including manual ones, count. At cap: create a deduplicated FLAKY alert and
leave the candidate blocking; manual attempts return 409. Lock the repository row to serialize
manual requests and ingest, including concurrent requests.

[decision] Lifecycle belongs to internal/quarantine; SQL lives in queries/, generated by sqlc.
Ingest, infra attribution, detection and release commit in one transaction. The existing schema
already provides quarantine history, JSONB evidence, stage labels and one active row per test.
No schema change or migration is required for P3.

Evidence records after_build_id, the greatest stored build ID in the repository at activation.
Only later inserted QUARANTINE results can advance release; retries of old builds cannot.
Recompute from stored history in started_at/build-ID order. PASSED advances; FAILED/ERROR/FLAKY
resets; infra/SKIPPED/missing do neither. K=10 by default. An upload retry replaces the same
stored build, so it never counts twice. Out-of-order or corrected uploads recompute an active
row's streak. Release records released_after_build_id; detection then accepts only newly
inserted blocking builds beyond that watermark. Stale evidence cannot immediately re-quarantine.

Build IDs are insertion watermarks, not a claim about when Jenkins ran the test. A previously
unseen old build arriving late can be evaluated with other history; started_at defines sequence.
Completed lifecycle decisions are durable audit records, not retroactively reversed when an
old upload is corrected. Such corrections require human review. Deleted tests need manual release.
If the observed test count shrinks, existing active rows stay active but no extra candidate is
admitted above the current cap.

## API

Every endpoint uses the existing Bearer ingest key.

| Method and path | Body / response |
| --- | --- |
| GET /api/v1/quarantine?repo=owner/name | Active array with IDs, names, rule, evidence, manual flag and pass streak; unknown repo=[] |
| POST /api/v1/quarantine | repo, class_name, method_name, reason; returns created ID |
| POST /api/v1/quarantine/{id}/release | reason; releases an active row |

Manual actions retain reasons in evidence and mark manual=true. 400 invalid input; 404 missing
test/active row; 409 existing quarantine or full cap. Internal errors are logged, not returned.

## CLI and shared library

Both formats are P1-verified newline Class#method files. Empty results are zero bytes.
Outage clears stale files, warns, exits 0. Write failure exits 1; invalid usage exits 2.
Validate identifiers: no wildcard/newline expansion; unsupported parameterized display names
fail safely to run-all. Requests carry a context deadline; response size is bounded.

Fetch one snapshot and copy it for the includes file. Absolute paths are necessary for Maven
reactor modules. The lab deletes its workspace at checkout. Blocking reports stay in
target/surefire-reports; quarantine XML uses target/surefire-reports-quarantine via the POM.
The reusable library contains no injected seed properties. It receives ordinary Maven options
from the consumer. The lab uses only Surefire; Failsafe quarantine selection is outside this gate.

Blocking test failures make the build UNSTABLE through junit; other Maven errors fail the build.
Quarantine failures use catchError and junit skipMarkingBuildUnstable. timedStage receives an
explicit stage outcome because a caught failure does not change currentBuild.currentResult.
Cancellation propagates. reportBuild uploads each XML part with X-BuildLens-Test-Stage.
Reject the same test in both stages instead of merging away a blocking failure.

Lab seed/Clock/order settings live in the separate lab repository. Random uses a seeded
SplittableRandom with injection policy 0.2 per invocation. Time uses Clock.fixed and advances
simulated time on reruns. Order uses seeded method shuffle and leaked static fixture state.
All are labelled injected. Reproduce with the same seed, simulated time and pinned runtime.
Running an order victim alone removes its polluter; it can therefore pass quarantine and later
fail in the full suite again. This illustrates a known limitation of pass-based release.

## Go for a Java reader

Structs, slices and pure functions replace service-class hierarchies here. Table-driven tests
play the role of parameterized JUnit tests. A pointer in a struct marks an optional value,
like an explicitly nullable Java field. Go 1.27 creates a distinct range variable each iteration,
so rule evidence can safely retain pointers to those per-iteration values.

store.New(tx) uses a pgx transaction like jOOQ with an explicit transaction context.
defer rollback is function-scoped finally (a no-op after commit). errors.Is finds wrapped
sentinel causes, unlike comparing an exception message. context carries cancellation/deadlines
explicitly through every DB/network call. Interfaces exist at HTTP boundaries where tests need
fakes. A repository row lock is the database equivalent of coordinating transactions with a
pessimistic lock; a process mutex would not protect a second server process.

The concurrency test uses sync.WaitGroup.Go to start goroutines and wait for their completion.
A buffered channel collects one result per request; this avoids sharing an unsynchronized result
list. The race detector checks Go memory access, while the real Postgres assertions check the cap.

## Verification workflow

The owner requested maximum quality and no agent Git commits/pushes. tools/p3-local.ps1 prepares
an uncommitted snapshot, records source SHA-256 hashes and configures a local job through Job DSL.
Loaded copies of vars/ gain only a return-this adapter for Jenkins load(); the original vars/ remain
normal shared-library scripts. The snapshot archive SHA-1 is used as the local tested-content
identifier; it is explicitly an archive digest, not a Git tree object. commit_sha is the lab's base
commit; it does not claim the uncommitted changes are committed.

The local bootstrap approves only its reviewed pipeline using
[ScriptApproval.preapprove](https://javadoc.jenkins.io/plugin/script-security/org/jenkinsci/plugins/scriptsecurity/scripts/ScriptApproval.html).
No click-based configuration, plugin installation, global signature approval or Git mutation.
Run `./tasks.ps1 drive 20`; raw evidence stays in ignored notes/experiments. The normal multibranch
job can use these changes after the owner reviews, commits and pushes both repositories.
